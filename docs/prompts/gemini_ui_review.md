# Gemini に頼む：画面の評価と修正案

使い方：スクリーンショットをまとめた ZIP（`giin-jinsei_ui_screenshots_v0.0.2-alpha.zip`）を Gemini に渡し、下の「プロンプト」以下を貼る。ZIP の中の `README.md` も同じ内容。返答はこのチャットに添付するか `docs/prompts/output.txt` に貼れば、Claude が今の作りに合わせて取り込む。

## プロンプト

日本を舞台にした政治シミュレーションゲーム「議員人生」の画面のスクリーンショットを添付します。画面のデザインを評価し、具体的な修正案を出してください。

### ゲームの説明

- 一人の政治家として、新人候補から当選を重ね、役職を上り、首相を目指す。毎月1つ活動を選ぶとひと月進む。野球ゲームの育成モード（能力のランク、特殊能力、毎月の練習の選択、出来事の会話）に近い遊び方。
- ブラウザで動く静的な Web アプリ（HTML と CSS と TypeScript。フレームワークは使っていない）。PC とスマホの両方で遊ぶ。
- 画面は2つの幅で並びを変える。PC（761px 以上）は家庭用ゲーム機風（上にタブ、下に状態の帯）。スマホ（760px 以下）はアプリ風（下に固定の5つのタブ、上に状態の帯、活動は丸いボタンの横スクロール）。
- 画面のモードが2つある。通常モード（初心者向け。秘書の助言とおすすめの活動を出し、細かい数字を省く）と、プロモード（経験点や関係などの数字をすべて出す）。

### 今のデザインの決まり

- 見た目は、前にあなた（Gemini）が作ったテンプレートを参考にしている。参考にした仕様は ZIP の `reference_ui_design_spec.md`、今の CSS は `reference_app.css` と `reference_app-ux.css`。
- 角の形は「押せるものは丸、読むだけのものは角」。押せるもの（ボタン、活動のカード、タブ、顔の札、名前の札）は丸角。読むだけのもの（パネル、情勢の欄、吹き出し、日付や資金の帯、ゲージ）は、左上と右下の角を斜めに切り落とした形（clip-path）。
- アイコンは SVG（紺の輪郭）。絵文字は使わない（端末で絵柄が変わるため）。
- 色は、明るい水色の背景、紺の濃いパネル、黄色とオレンジの強調、政党ごとの色。
- 押せる場所は44px以上。ホバーに頼らず「1回押すと選んで説明、もう1回で実行」。

### 守ってほしいこと

1. 実在のゲームの名前、キャラクター名、ロゴ、絵柄を使わない（参考の作品名を書くのはよいが、そっくりにはしない）。
2. どの政党、政治的立場にも肩入れした色づかいや表現にしない。
3. 静的な Web アプリで実装できる案にする（画像素材を大量に作る案や、サーバーが必要な案は「大きな案」に分ける）。
4. 日本語で答える。

### 出してほしいもの

1. **全体の評価**：良いところと、いちばん直すべきところを3つずつ。情報の多さ（シミュレーションなので数字が多い）と、初めての人の分かりやすさの両立について特に意見がほしい。
2. **画面ごとの問題と修正案**：上の表の画面ごとに、目立つ問題（読みにくい、詰まりすぎ、目線が迷う、押せるか分からない、スマホではみ出す、色がぶつかる、など）と、その直し方。直し方はできるだけ具体的に（どの要素の、大きさ・余白・色・並び・文字の太さをどう変えるか。CSS の書き方で示せるものはそれでよい）。
3. **共通の部品の改善**：ボタン、カード、パネル、タブ、状態の帯、ポップアップ、ゲージ、ランクの文字、政党の色の札などの部品について、全体で統一したほうがよいこと。
4. **優先順位**：直す順番を、効果が大きく手間が小さいものから10個。
5. **大きな案**（任意）：今の作りから離れるが良くなりそうな案を3つまで。

出力は Markdown の見出しと表と箇条書きでまとめてください。
