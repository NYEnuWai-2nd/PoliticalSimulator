# 設計メモ

これまでの検討で決めたこと、提案したことをまとめる。数値は `data/stats/member_stats.json` と `data/stats/shugiin_turnover_1947_2024.csv` による。

## 1. キャラクターの構成（パワプロ方式）

### 基礎能力（G〜Sの7段階）

| 能力 | 影響する場面 |
|---|---|
| 弁舌 | 討論、演説、国会質疑 |
| 政策 | 法案作成の速さと質 |
| 調整 | 根回し、連立協議 |
| 知名度 | 無党派層の票、メディアへの露出 |
| 組織 | 後援会や支援団体の動員 |
| 資金 | 献金、資金集め |

### 地盤（パワプロの弾道に当たる、1〜4）

1は比例頼みまたは落下傘候補、2は接戦区、3は比較的安定した選挙区、4は負けない選挙区。自民党の衆議院議員（2026年）は小選挙区当選233人、比例単独39人、比例復活23人で、各段階の割合の根拠にできる。

### 役職の適性（パワプロの守備位置に当たる）

選対、国対、政調、広報、閣僚、党務の6つ。得意な役職が一つ、そこそこ務まる役職がいくつかある形にする。

### 思想（能力とは別のパラメータ、各軸 −3〜+3）

経済（市場重視 ↔ 再分配重視）、財政（積極財政 ↔ 財政規律）、安全保障（抑止重視 ↔ 対話重視）、社会的価値観（伝統重視 ↔ 多様性重視）、統治（改革・分権 ↔ 安定）の5軸。

これとは別に次の二つを持たせる。

- 信念の固さ：党の方針にどれだけ逆らいやすいか。能力は低いが一つの争点だけは譲らない議員が生まれる。
- 党への忠誠：政界再編（合併、分裂）のときに党を移るかどうかを決める。

### 特殊能力

| 色 | 性質 | 例 |
|---|---|---|
| 金特 | 強力で珍しい | 選挙の神様、根回しの鬼、論破王 |
| 青特 | 経歴類型に結び付いた標準的な能力 | 霞が関人脈（官僚出身）、ドブ板（地方議員出身）、組織票（組織内候補）、無党派に強い（知名度型）、専門家答弁（専門職）、行政手腕（首長経験） |
| 赤特 | 欠点 | 失言癖、比例頼み、地元不在、調整下手、炎上体質 |
| 緑特 | 状況によって利点にも欠点にもなる | 一匹狼、劇場型 |

## 2. 経歴類型（キャラクター生成の第一段階）

実在議員の経歴をキーワード規則で分類した12類型（分類不能を除く）。

地方議員からの叩き上げ、官僚出身の政策通、経済人、知名度型、専門職、地盤継承型、学者・国際派、組織内候補、首長経験の行政型、現場の代弁者、安全保障の実務家。

わかったこと：

- 構成比は年によってほとんど変わらず（2024年と2026年でほぼ同じ）、政党ごとの性質と考えられる。架空政党ごとにテンプレートを一度作れば使い回せる。
- 院によって違う。参議院は知名度型（約18%）と組織内候補（約7%）が多く、衆議院は組織内候補がほぼいない（約1%）。テンプレートは政党別かつ院別に作る。
- 世襲は紹介文に明記されないことが多く、自動分類では少なく出る。世襲の比率は別のパラメータとして設定する。

## 3. 生成の手順

1. 架空政党と院ごとの重みで経歴類型を選ぶ。
2. 類型に対応した基礎能力のランク範囲と特殊能力の候補を決める。
3. 当選回数区分（新人28%、中堅39%、ベテラン26%、重鎮7%が現職の分布）と年齢を決める。
4. 名前生成器で生まれ年代に合った名前を付ける。
5. ランダムな変動を加える。

例：与党系・官僚出身・当選4回 → 政策A、調整B、弁舌C、知名度D、組織C、資金C、地盤3。特殊能力は霞が関人脈、数字に強い。欠点は街頭演説が苦手。

## 4. 成長（パワプロのサクセスに当たる議員人生モード）

経験点は選挙点、政策点、人脈点、発信点、資金点の5種類。新人議員から政務官、副大臣、大臣、党首へと育てる。

当選回数の中央値は4回で、10回以上当選するのは約8%。重鎮まで育つのは珍しい成功例として扱う。

## 5. 選挙の仕組みへの示唆

- 全国的な風：2009年、2012年、2026年のように一つの政党が大きく議席を失う選挙が繰り返し起きている。新人の割合は通常13〜26%だが、2009年は33%、2012年は38%。全国的な支持の振れ幅の変数を用意し、地盤の弱い選挙区から入れ替わるようにする。
- 浪人中の議員：途中で落選して返り咲いた人は31%。2026年には元職が66人戻った。落選した議員を消さずに「浪人中」として残し、地盤や資金が少しずつ減りながら返り咲きを狙う形にする。
- 政界再編：32%が二つ以上の政党名で当選している（合併、改名を含む）。合併、分裂のイベントを用意する。

## 6. AIについて（将来の検討事項）

- 当面は使わない。
- 使う場合は、戦略判断を従来型のゲームAI、言葉（演説、会見、交渉の返答）をLLMに任せる。LLMは合法な行動の一覧から選ぶだけにし、結果はゲームのコードが判定する。
- LLMを使うのはライバル一勢力だけにする案が有力。
- 静的ホスティングなので開発者のAPIキーは埋め込めない。プレイヤーが自分のAPIキーを入力する方式か、ローカルモデルを任意で使う方式にする。LLMなしでも完結して遊べるようにする。
- Steamで出す場合、実行中にAIが生成する内容には安全策の説明が必要。
